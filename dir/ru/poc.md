# Proof of Concept: CG/CI/CD Pipeline Architecture

Данный проект представляет собой **PoC (Proof of Concept)** системы автоматизации жизненного цикла разработки ПО, расширяющей традиционный подход CI/CD стадией непрерывной генерации (**Continuous Generation**).

---

## 1. Концепция системы
Основная идея заключается в смещении фокуса автоматизации на этапы, предшествующие написанию исходного кода вручную.

**Классический CI/CD:**
`Разработчик (код) → Git → CI/CD Pipeline → Build/Deploy`

**Предложенный подход (CG/CI/CD):**
`Проектные артефакты → Code Generation → Сгенерированный код → CI/CD Pipeline → Build/Deploy`

---

## 2. Архитектура PoC

### 2.1. Репозитории
*   **cg-source-repo**: Основной репозиторий, содержащий метамодель, генератор и логику конвейера.
*   **generated-app-repo**: Целевой репозиторий, куда поступает результат генерации (Spring Boot приложение).

### 2.2. Компоненты системы
*   **Project Artifacts**: "Источник истины" в формате `model.yaml` и диаграмм PlantUML. Выполняют роль формальной модели проекта.
*   **Generator**: Инструмент на базе **Python + Jinja2**. Анализирует сущности (entities) из YAML-файла и трансформирует их в Java-код.
*   **CI/CD Layer**: Слой автоматизации на базе **Jenkins** и **Maven**, обеспечивающий валидацию, сборку и подготовку Docker-контейнеров.

---

## 3. Функциональные возможности
На текущем этапе PoC обеспечивает:

1.  **Генерация Backend-слоя**: Автоматическое создание Entity, Repository, Service и Controller для каждой сущности.
2.  **REST API**: Генерация стандартных эндпоинтов (GET, POST, DELETE) для взаимодействия с данными.
3.  **Интеграция с БД**: Автоматическая настройка Spring Boot + JPA (H2 Database) для создания таблиц и операций сохранения.
4.  **Автоматизированная сборка**: Сгенерированное приложение готово к компиляции через Maven и запуску.
5.  **Регенерация**: При изменении модели в `model.yaml` (например, добавлении новых полей или сущностей), pipeline обновляет структуру приложения.

---

## 4. Ограничения (Limitations)
Для объективной научной оценки зафиксированы следующие ограничения прототипа:
*   **Сложность связей**: Отсутствие поддержки сложных отношений (OneToMany, ManyToMany).
*   **Бизнес-логика**: Генератор фокусируется на CRUD-операциях; сложные Workflow и правила валидации требуют ручной доработки.
*   **Frontend**: Система генерирует только Backend часть.
*   **Deployment**: Реализована структура Docker, но полноценное развертывание в Kubernetes или облачные среды находится вне рамок PoC.
*   **Интеграция CASE**: Используются упрощенные форматы (YAML), а не промышленные CASE-инструменты (Enterprise Architect и др.).

---

## 5. Научная и практическая ценность
Проект демонстрирует практическую реализуемость методологии **Model-Driven Engineering (MDE)** в современных DevOps-конвейерах. 

> **Ключевой вывод:** Формальные проектные артефакты могут служить первичным источником данных для конвейеров поставки ПО, минимизируя рутинное написание шаблонного кода и снижая риск расхождения между архитектурным проектом и реализацией.

---

## 6. Соответствие академическим требованиям
*   **Автоматизация ранних этапов**: Да (моделирование → код).
*   **Генерация на основе информации о проекте**: Да (`model.yaml` → Java App).
*   **Использование CI/CD технологий**: Да (Jenkins, Maven, Git, Docker).
*   **Работоспособность**: Сгенерированный код успешно проходит стадию Build и запускается как исполняемый сервис.

---

## 7. Резюме / Final Definition
*The proposed Proof of Concept demonstrates the feasibility of extending traditional CI/CD pipelines with an additional Continuous Generation stage, where formal project artifacts are transformed automatically into executable software components.*
